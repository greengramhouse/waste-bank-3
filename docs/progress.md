## ทำเพิ่มเมื่อ 4 ก.ย. — ข้อมูลสด

ระบบอัปเดตเองแล้วเมื่อเครื่องอื่นบันทึกรายการ ไม่ต้องกดรีเฟรช
และเลิกโหลดธุรกรรมทั้งปีมาค้างไว้ ทำให้อ่านน้อยลงมากและปลดข้อจำกัด `MAX_TX`

| | เดิม | ตอนนี้ |
|---|---|---|
| แอดมินล็อกอิน 1 ครั้ง | ~5,300 อ่าน | ~800 อ่าน |
| เห็นรายการที่ครูอีกคนบันทึก | ต้องกดรีเฟรช | ขึ้นเอง |
| ธุรกรรมเกิน 5,000 รายการ | ข้อมูลขาดเงียบ ๆ | ไม่มีปัญหา ไม่มีใครดึงทั้งปีค้างไว้ |

**บั๊กที่เจอและแก้ระหว่างทาง**
- `balanceDelta()` ตัดสินฝาก/ถอนจากค่าที่คูณ sign แล้ว ทำให้การลบรายการฝาก
  ไปเพิ่ม `totalWithdraw` แทนที่จะลด `totalDeposit` (ยอดคงเหลือรวมยังถูก แต่ช่อง
  ยอดฝาก/ยอดถอนเพี้ยน) — แก้แล้วและซ่อมข้อมูลด้วย `npm run balances`
- ฟังก์ชันวาดหน้าที่เป็น async ถูกเรียกซ้อนกันแล้วแถวซ้ำสองเท่า — แก้ด้วย `renderSeq`

รายละเอียดทั้งหมดอยู่ใน [`realtime-plan.md`](./realtime-plan.md)

## เครื่องมือที่ใช้บ่อย

```bash
npm run serve        # เปิด http://localhost:5000/app.html
npm run test:rules   # ทดสอบสิทธิ์ 38 ข้อกับฐานจริง (ล้างข้อมูลทดสอบให้เอง)
npm run verify       # ตรวจความครบถ้วนของข้อมูล
npm run balances     # คำนวณยอดคงเหลือใหม่จากธุรกรรมจริง (ใส่ --check เพื่อดูเฉย ๆ)
npm run deploy:rules # ติดตั้ง Rules + indexes ใหม่หลังแก้

npm run set-passwords          # ดูรหัสที่จะสุ่ม (ใส่ -- --apply เพื่อตั้งจริง)
npm run handout                # สร้างใบแจ้งรหัสไว้พิมพ์แจก (docs/handout-passwords.html)
npm run notice                 # ดูป้ายที่จะแปะบน student.html (ใส่ -- --apply เพื่อแปะจริง)
npm run live                   # ดูว่าหน้าแรกของเว็บตอนนี้เป็นระบบไหน
npm run live:new / live:old    # สลับหน้าแรกไประบบใหม่ / ย้อนกลับระบบเดิม
```
